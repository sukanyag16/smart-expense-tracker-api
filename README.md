# Smart Expense Tracker API

A REST API for managing personal expenses, built with FastAPI and Python.

The API supports creating, viewing, filtering, totaling, and deleting expenses. Data is persisted locally in a JSON file, keeping the implementation lightweight while preserving data between server restarts.

## Features

- Add a new expense
- View all expenses
- Filter expenses by category
- Calculate total expenses
- Calculate total expenses by category
- Delete an expense by ID
- Input validation and error handling
- Local JSON file persistence
- Automated API test suite
- Interactive OpenAPI/Swagger documentation

## Tech Stack

- Python 3.12
- FastAPI
- Pydantic
- Uvicorn
- Pytest
- HTTPX
- JSON file storage

## Installation

Python 3.12 is recommended.

From the repository root, install the dependencies:

```bash
pip install -r requirements.txt
```

## Running the Server

From the repository root, run:

```bash
uvicorn src.main:app --host 127.0.0.1 --port 8000
```

The API will be available at:

`http://127.0.0.1:8000`

## Running Tests

From the repository root, run:

```bash
pytest
```

The test suite uses isolated temporary JSON files, so running the tests does not modify `src/expenses.json`.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| POST | `/expenses` | Create a new expense |
| GET | `/expenses` | View all expenses |
| GET | `/expenses?category=Food` | Filter expenses by category |
| GET | `/expenses/total` | Calculate the overall expense total |
| GET | `/expenses/total?category=Food` | Calculate total for a category |
| DELETE | `/expenses/{expense_id}` | Delete an expense |

## Example

### Create an Expense

Request:

```http
POST /expenses
Content-Type: application/json
```

```json
{
  "title": "Lunch",
  "amount": 250.5,
  "category": "Food",
  "date": "2026-08-01"
}
```

Example response:

```json
{
  "title": "Lunch",
  "amount": 250.5,
  "category": "Food",
  "date": "2026-08-01",
  "id": 1
}
```

The API returns HTTP `201 Created` after successful creation.

## Validation

The API validates incoming expense data:

- `title` must be non-empty and is trimmed of surrounding whitespace.
- `amount` must be greater than zero.
- `category` must be non-empty and is trimmed of surrounding whitespace.
- `date` must be a valid ISO date in `YYYY-MM-DD` format.

Invalid request bodies return HTTP `422 Unprocessable Entity`.

Deleting an expense that does not exist returns HTTP `404 Not Found`.

## Design Decisions

### JSON Persistence

A local JSON file was used instead of a database because the assignment does not require a database. This keeps the solution lightweight while still providing persistence across server restarts.

### Separation of Concerns

API routing, validation models, and persistence logic are separated into `routes.py`, `schemas.py`, and `storage.py`. This keeps each component focused without introducing unnecessary layers for a small API.

### ID Generation

Expense IDs are generated by the server using the highest existing ID plus one rather than the number of stored expenses. This avoids duplicate IDs after an expense is deleted.

### Category Filtering

Category filtering is case-insensitive. For example, `Food`, `food`, and `FOOD` match the same category.

### Test Isolation

Automated tests redirect persistence to a fresh temporary JSON file for every test. This prevents tests from depending on previous test data or modifying application storage.

## Assumptions

- Expense IDs are generated by the server.
- Amounts must be greater than zero.
- Dates use ISO `YYYY-MM-DD` format.
- Categories are free-form, non-empty strings.
- Category matching is case-insensitive.
- Filtering by a category with no expenses returns an empty list.
- Calculating the total for a category with no expenses returns zero.

## Future Improvements

For a production system, possible improvements include database-backed persistence, fixed-precision monetary storage, authentication, pagination, and structured logging. These were intentionally kept outside the scope of this assignment.
